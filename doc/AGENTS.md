## AGENTS.md 定位
- `AGENTS.md`：只放协作流程、触发机制、文档入口与 skill 路由规则，不承载业务实现细节。
- `doc/agent-coding-rules.md`：放跨场景生效的 MUST/SHOULD/MUST NOT（并发、Redis、协议一致性、验收基线等）。
- `skills/*/SKILL.md`：只放特定任务场景的入口定位、操作步骤、排查路径；若引用全局硬规则，链接到 `doc/agent-coding-rules.md`，避免重复维护。

## 编码规范入口
- 新智能体进入项目后，先读取：`doc/agent-coding-rules.md`。
- 若与临时任务指令冲突，以用户当轮明确要求为准。

## 架构与代码定位入口
- 需要快速了解服务架构、服务职责、启动入口时，先读：`skills/server-architecture/SKILL.md`。
- 需要了解本地运行、配置渲染、服务启停时，先读：`skills/run-and-env/SKILL.md`。
- 需要查看历史设计资料与流程图时，参考：`doc/design/`。
- 常见代码入口定位：
  - 服务启动入口：`src/*svr/scripts/main.go`
  - gamesvr 客户端协议入口：`src/gamesvr/scripts/apps/*App.go`
  - gamesvr 核心业务状态与逻辑：`src/gamesvr/scripts/model/*.go`
  - 运行配置模板：`run/<service>/conf/*.j2`



## 工作流程：Plan 模式
- 接到需求后，先进入 Plan 模式梳理需求、边界与实施路径。
- Plan 阶段默认只做只读分析、方案比较与影响评估，不直接进入修改或执行。
- 仅在信息不足或存在关键不确定性时提问；信息充分时，直接给出可执行方案。
- 用户确认前，不执行代码修改、脚本运行、配置变更等动作。

### Plan 输出顺序
- 先给“方案选项与取舍”，再给“推荐方案”和“执行步骤”。
- 优先按统一模板输出，减少遗漏与自由发挥。
- 步骤要可执行、可验证，避免空泛表述。

### Plan 输出模板
进入 Plan 模式后，优先按以下结构输出：

1. 目标理解
   用 1~3 句话复述需求、范围、非目标。

2. 方案选项与取舍
   至少给出 2 个方案，说明适用场景、优点、缺点。
   明确推荐方案及原因。

3. 执行步骤
   按顺序列出 3~7 个会实际执行的步骤。

4. 风险与前提
   说明关键依赖、潜在回归点、兼容性影响或实施前提。

5. 验收标准
   明确完成判定方式，优先写可观察结果。

6. 待确认项
   仅在信息不足或存在关键分歧时提问。
   若信息已足够，明确写“无，等待确认执行”。


## 协作约束
- 未经用户确认，不执行破坏性命令（如 `git reset --hard`、强制删除）。
- 未获确认前，只允许进行只读分析（读文档、读代码、影响评估），不进行代码修改、脚本写入、配置变更。
- 遇到不确定需求，先回到 Plan 模式补齐任务信息。
- 若用户请求的是方案讨论、评审、优化建议，默认停留在 Plan/建议层。
- 仅在用户明确要求实施时进入执行态；确认信号应明确，例如“按方案 B 执行”“开始修改”“继续实施”。

## Skills
可用 skills 清单与路径索引见：`skills/README.md`。

### How to use skills
- Discovery: 可用 skills 列表在 `skills/README.md`（名称 + 描述 + 路径）。
- Trigger rules: 当用户明确提到某个 skill 名称，或任务内容明显符合描述时，必须使用对应 skill。
- Missing/blocked: 如果指定 skill 无法读取，简要说明原因并用最佳替代方案继续。
- Progressive disclosure:
  1) 决定使用某个 skill 后，先打开其 `SKILL.md`。
  2) 若 `SKILL.md` 指向 `references/` 等资料，仅在需要时加载。
  3) 若有 `scripts/`，优先运行或修改脚本而不是重复手写。
  4) 若有 `assets/` 或模板，优先复用。
- Coordination: 多个 skill 同时适用时，选择最小集合并说明使用顺序。
- Context hygiene: 控制上下文体积，避免无必要的全文加载。

## 续聊摘要输出要求
- 收到 `存档` 指令后，必须输出“可直接复制到新对话窗口”的摘要，确保新 agent 可无缝接续。
- 摘要必须覆盖目标、约束、状态、代码定位、验收与下一步，不得只给泛化描述。
- 摘要应同步写入按日期与需求组织的文件（建议：`doc/archive/YYYY-MM-DD/<需求名>.md`）以减少上下文漂移。
- 标准模板见：`doc/agent-summary-template.md`。
